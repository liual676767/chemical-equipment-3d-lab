# 内容维护指南（集中配置 + 校验门禁）

## 核心模拟操作检查

项目规则见根目录 `AGENTS.md`。修改后先运行 `npm run test:core`，检查设备搜索、学习页面与滑条、一次引导拆装，以及工坊添加直管、连接、保存后刷新恢复。首页设备卡缩略图为静态 PNG（`public/thumbs/`，来源为现有真实模型），设备几何变化后运行 `npm run thumbs`。每次运行使用独立浏览器数据并在 `outputs/core-flow/` 新建结果目录；失败时记录失败步骤并尽可能保存截图。测试默认在本机空闲端口自动启动开发服务，并在结束后停止该服务。可用 `CORE_TEST_BASE` 指定已有测试地址，用 `EDGE_PATH` 指定浏览器。受影响的设备仍须按下文运行完整检查和专项检查；核心检查通过不等同于所有设备和三维几何均已验收。

工坊导入内容版本核对与损坏数据处理尚需复核；下文旧描述不代表已经完成这些检查。

当前阶段按用户要求采用「集中内容配置 + 维护文档」方案，可视化内容管理后台留待后续。所有设备内容集中在一处，改动必须过校验门禁。

## 2. 修改内容的标准流程

1. **改配置**：在 `devices.ts` 修改/新增设备或零件。必填字段见 `types.ts`；零件必须同时给出 `joint`（welded/bolted/fitted/anchor）与 `role`（fixed/removable/display），且 `role` 与旧 `fixed`/`removable` 标记一致（校验器强制）。
2. **补建模**：新零件必须在 `builders.ts` 有对应几何，否则校验报「缺少模型」。新设备还须在 `interactions.ts` 有至少 1 个结构专属互动、在 `principle.ts` 有原理动画编排（当前 18 台均已覆盖）。
3. **升版本**：任何影响学习内容或拆装逻辑的改动，必须升级该设备 `contentVersion`（格式 `YYYY-MM-DD.N`）。旧练习进度将按不兼容自动作废（收藏与成绩保留），这是预期行为。
4. **过门禁**：`npm run validate:content`（必填项、重复编号、缺失模型、无效安装目标、步骤依赖、任务引用）。`npm run build` 已内置该校验，失败即阻断构建。改动微沸喷烧流程数据时另跑 `npm run validate:boil`（引用/方向/介质/连通/流线连续性；待确认项必须逐项列出）。
5. **预览验证**：`npm run dev` 打开受影响设备，逐模式目检；再跑 `npm run verify`（实训室全流程，含首页导航/搜索/收藏叠加、18 台设备加载/爆炸复原/原理动画、新增设备引导拆装与手机端，当前 174 项）、`node scripts/verify-workshop.mjs`（工坊 51 项真实操作）、`npm run smoke:prod`（生产冒烟）；首页设备卡使用 `public/thumbs/` 静态缩略图，设备几何或外观变更后运行 `npm run thumbs` 重新生成；改动导航/工作台布局时另跑 `node scripts/acceptance/a11y-redesign.mjs`（键盘、焦点、触屏菜单与对比度 19 项）；改动全流程装置时另跑 `node scripts/verify-plant.mjs`（64 项：数据关系/自检、接口与管线卡、阀门联动、上下游追踪、四种模式、层/工序、教学、流程图、拾取、移动端）。流程数据改动必须先保证 `window.__plant.audit()` 0 问题且连接/管线/流向指标为 100%。改动微沸喷烧设备模型/接口时另跑 `node scripts/verify-boil-models.mjs`（14 类模型、36 个数据接口、锚点/法线/边界一致性 + 截图）；改动管道/流体时另跑 `node scripts/verify-boil-piping.mjs`（20 项）与 `node scripts/verify-boil-fluid.mjs`（37 项：全开/关阀/部分开度传播、暂停/速度/箭头、HUD 与三维交互 + 截图）；改动区域分层、流程树、`#/boil` 页面或镜头时另跑 `node scripts/verify-boil-areas.mjs`（52 项：五区/流程树/设备与管线点选/上下游/复位/无重建/900px 与 390px 窄屏）。若同一工作副本有并行会话正在编辑 `src/boil/*`，长时间全站回归应使用冻结源码副本（`outputs/p5-dev-freeze`）或构建副本，避免 Vite 整页热重载打断测试；不要把冻结副本当作发布源。
6. **同步文档**：更新 `docs/sources-and-review.md` 来源记录、重新生成 `docs/models.md`、在 `docs/round-log.md` 记录本轮改动与验证结果。
7. **发布**：按站点发布流程重新构建发布；发布后跑 `node scripts/walk-published.mjs`（线上实训室拆装主流程 + 工坊放置/连接/保存重开 + 全流程入口/运行/返回，纯 DOM）。

## 3. 校验门禁检查项（scripts/validate-content.mjs）

- 设备与零件必填字段非空；设备/零件/任务编号唯一；
- `role` ⇔ `fixed`/`removable` 标记一致；`joint`/`role`/任务 `mode` 取值合法；
- `pos`/`explodeDir` 为三元数组，`explodeDist` 非负且方向非零；
- `assemblyOrder` 只含存在的可拆卸零件、无重复；
- `prereq`（安装前置）必须先于自身安装；`removeAfter`（拆卸前置）必须先于自身拆卸、不含自身；
- 观察任务引用的零件存在；自动完成类任务所在设备必须开放练习；
- `builders.ts` 覆盖每台设备与每个零件编号。

工坊侧（同一脚本内）：

- 55 对象必填字段非空、编号唯一、大类/批次/状态/能力取值合法；
- 可搭建（ready）对象在 `geometry.ts` 有对应建模分支，接口非空且每个接口位置/朝向为三元数组、朝向为单位向量；
- 开发中（dev）对象不要求模型，但资料字段同样强制。

### 3.1 工坊内容变更注意

- 新增可搭建对象：`catalog.ts` 登记 → `geometry.ts` 建模 → `layout.ts` 接口（朝向必须与几何管口一致，门禁查单位向量但一致性需人工/实测核对）→ 需要时补 `specs.ts` 配对预设 → 跑 `verify-workshop.mjs`。
- 工坊内容版本 `WORKSHOP_CONTENT_VERSION`（`src/workshop/types.ts`，当前 2026-11-16.1）：影响已保存方案兼容性的改动须升版本；方案导入按 app 标识 + schema + 内容版本校验。
- 工坊存储独立于实训室：localStorage `chem3d-workshop:v1`（方案列表），实训室为 `chem3d-lab:v1`，互不影响。

### 3.2 微沸喷烧流程数据与接口/连接/路由/流体/区域/追踪/播放校验（`npm run validate:boil`，Phase 1–6）

- Phase 1：设备/管线/端口/工序/区域/流线/介质 id 唯一，必填字段非空；管线端点引用存在的设备+接口，起点为出口、终点为入口，介质在两端接口声明；工艺区/工序/设备归属一致；流线设备顺序与管线端点逐对匹配；未连接接口和不在主流线中的设备必须显式标 `pending-confirmation`；汇总待确认缺口；仅有待确认警告时退出码为 0，但必须人工核对输出。
- Phase 2：每台设备必须有 `modelKey` 且模型已注册；每个数据接口必须能匹配模型锚点（`modelPortId` 缺省等于 `port.id`），id/角色/介质/边界标记一致；模型锚点坐标/法线有效且法线归一化；18 个实例映射 14 类模型（喷枪 4 个实例共用 1 类模型）。
- Phase 2 连接图：13 条有向边、26 个已连接接口、2 个边界接口、8 个待确认接口、0 个未连接且未标待确认接口；物料流与烟气流的上游/下游路径必须与设备顺序一致；不得有重复连接、孤立连接或与流线冲突的有向环。
- Phase 3 路由：18 个教学布局齐全且无重复；每条工艺管线必须有 `route`，管径等级与两端模型接口等级一致；端点必须沿端口法线、线段轴对齐且无退化；设备避让盒外扩 0.3 m 做线段相交检查（仅豁免起终点设备的对应端口短节）、设备避让盒两两重叠 0.05 m、支架落点 XZ 占位；每条管线 1 个示意阀（没有满足间隙的管段才警告）、支架只落水平管段且间距不超过配置上限；工艺线三通/变径必须为 0（部件库单独演示）。
- Phase 4 流体：13 条管线各 1 个示意阀且阀 id/型式与路由配置一致、阀位比例有效；两条流线不得重复引用管线、必须按设备顺序覆盖全部 13 条管线；全开时 13 条全部流动且未供料设备只能是四根喷枪；逐阀关闭时本管 `halt` 在阀位、同流线下游 `off`、上游与其他流线 `full`；逐阀部分开度时本管与同流线下游 `full+throttle`、上游与其他流线不节流；全部关闭时两条流线首管 `halt`、其余 `off`、供料设备只剩两个流线源。
- Phase 5 区域：每台设备必须且只能归属一个区域，区域设备清单与设备 `areaId` 完全一致；每条管线按 `areaId` 唯一归属（跨区管线归下游区），区域管线清单与之一致；区域上下游声明必须与跨区管线实际连接完全一致、对称、无自环/有向环、且从首端可达全部区域；首端区域必须有流程边界入口、末端必须有边界出口；区域三维范围必须由本区设备模型包络建立且互不重叠；四根喷枪必须全部在燃烧处理区、挂到二燃室作 `parallel-branch`，不得有喷枪—喷枪管线或进入主流线。
- Phase 6 追踪/播放：追踪图必须由 18 设备节点、13 条工艺边与 4 条喷枪平行支路边构成；喷枪不得生成串联边，不伪造工艺上下游；水洗塔上游/下游路径、二燃室完整路径含 4 根平行支路；合成多分支必须返回 2 条以上路径；合成“烟囱→SMP”回流必须识别环并终止（不无限递归）；实际流程必须 0 环。播放必须 15 步顺序与用户清单一致、覆盖全部 18 设备/13 管线、四根喷枪为第 6 步；状态机开始/暂停/4×/完成/停止的进度与状态必须正确；速度档位只能为 0.5/1/2/4。
- 该命令不检测管—管碰撞、结构强度、应力、真实流体（CFD/流量分配/压降）与真实工程路由；Phase 4 只校验教学流线传播逻辑，不计算流量、压力、温度或停留时间；Phase 5 只校验教学区域归属/上下游/范围，不表示工程分区或现场接管。模型包围盒/锚点位置由 `scripts/verify-boil-models.mjs` 复核，管道几何/整线布局由 `scripts/verify-boil-piping.mjs` 复核，粒子/箭头/阀门联动由 `scripts/verify-boil-fluid.mjs` 在浏览器中复核，区域分层/流程树/联动由 `scripts/verify-boil-areas.mjs` 在浏览器中复核；追踪/播放/底部控制/二维地图由 `scripts/verify-boil-playback.mjs` 在生产构建上复核；不能替代工程设计、装置总平面与专业评审。

## 4. 版本与回滚

- **内容版本**：每设备 `contentVersion`；学习记录（练习进度、观察任务）按版本保存，跨版本自动作废并提示。
- **记录结构版本**：localStorage `schema`（当前 2），旧结构自动迁移。
- **代码回滚**：发布前保留上一版 `dist/` 备份（建议复制为 `dist-backup-<日期>/`，不纳入站点发布目录）。回滚 = 用备份目录重新走发布流程；内容回滚 = 还原 `devices.ts` 对应版本并把 `contentVersion` 一并还原（避免记录误作废）。
- **用户记录备份**：界面「学习记录管理 → 导出记录（JSON）」；导入时校验 `app` 标识并按当前内容版本过滤不兼容进度。

## 5. 新增设备的门槛

第一轮曾约定「三台设备完善前不新增」；第三轮用户明确要求扩充设备库，该门槛已被取代，当前设备库为 18 台（13 台开放引导式拆装）。此后新增设备除上述流程外，须补齐：学习目标、≥4 个观察任务、结构依据记录（厂商/教材/高校来源，核对结论记入 sources-and-review.md）、≥1 个结构专属互动、原理动画、（如开放拆装）完整 `assemblyOrder` 与前置/后置约束。焊接/铸造为主的设备可标「拆装练习未开放」，但须如实说明原因。工坊新增可搭建对象按 §3.1 流程，与实训室设备编号独立、避免重复条目（见 workshop-catalog.md 区分说明）。
